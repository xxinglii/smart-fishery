**最简单**：双击 `index.html`，用任意现代浏览器打开。无需服务器、无需构建、无需联网（字体走 CDN，离线时自动降级为系统字体）。

## 这个原型想说明什么

它不是"又一个漂亮的仪表盘"。它是一个**立场**的可视化：

> **用 ESP32 做"传感 + 决策 + 告警"非常靠谱；
> 用它（或任何相机）做"数鱼"不靠谱。
> 而好消息是——你不需要数清鱼，也能把喂料这件事做好。**

所以你会在这个界面里看到三件通常不会出现在 Demo 里的东西：

1. **每个数字都带证据等级角标**（A / B / C），鼠标悬停可以看到它的来源与局限。
   A = 本塘实测 / 同行评议 / 政府文件；B = 经验值待校准；C = 原型演示值。
2. **没有点估计，只有区间**。存塘量是 `5,210 – 8,940 尾`，不是 `7,450 尾`。
   界面会告诉你这个区间为什么这么宽。
3. **"不能做"排在"能做"前面**。视觉分析页先讲几何否决与公开成绩单（mAP 38.93%），再讲它能贡献什么。

## 自检

```bash
node selftest.js
```

用一个最小 DOM 桩跑通 **8 个视图 × 3 个情景 = 24 种组合**，并断言：

- 输出 HTML 中不含 `undefined` / `NaN` / `[object Object]`（模板 bug 的典型症状）
- 决策链自洽：下限 ≤ 上限、推荐落在区间内、上限不超硬封顶、钳制系数 ∈ [0,1]
- **缺氧情景必须归零，非缺氧情景不得归零**
- **高温情景必须只减不增，常态情景必须不钳制**
- 传感序列的极值必须与情景声明的日最高水温 / 夜最低溶氧一致

## ⚠️ 数据声明

**本原型的全部数值均为演示用模拟数据，不可用于生产决策。**

其中标记为 A 级的证据条目（来源、数字、结论）是真实的，来自本项目的调研；
但**塘口档案、传感器读数、台账记录、节点状态全部是编造的**，
用于演示交互与决策逻辑，不代表任何真实塘口。

真实部署时：

- 传感器数据应由 ESP32 节点经 MQTT 上报
- 台账数据应由用户在录入界面填写
- 投喂决策应由确定性模块计算，**LLM 无权生成任何数字**
