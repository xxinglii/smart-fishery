# 帖子 006 · ESP32 + 摄像头数鱼 + 多传感器路线的可行性评估与交付

> **触发**：用户提出新设想——「改做 ESP32，通过相机测鱼数量，然后通过各家传感器，
> 根据说明指导渔民撒多少粮，包括 GPS 位置、温度等等」。
> **产出**：两份 Word 交付文档 + 一个原型 Demo 网站 + 两份专项调研报告。

## 一、结论：分模块判定，不是整体可行或不可行

用户把四件独立的事打包成了一个设想，必须先拆开。**判定结果与项目既有结论高度一致**——
既有的三路调研 + 五轮对抗已经否决过摄像头路线，本轮只是把它从「推断」升级为「有土塘实测数字的结论」。

| # | 模块 | 判定 | 新证据 |
|---|---|---|---|
| 1 | 摄像头测鱼的数量 | ❌ **不可行** | 纯光学在池塘场景公开最好成绩只到 **mAP 38.93%**（DePondFi'23，15 队参赛）；加声学做融合，中国水科院淡水中心在真实土塘也只到 **85–92%**，且是「体量/密度」而非逐尾；华中农大声呐方案 **84.5%** |
| 2 | 各家传感器 | ✅ **靠谱** | ESP32 的本职工作。且既有结论已有对照验证：**溶氧 + 水温 + 体重的系统即可让 FCR 降 11.73%**（农业工程学报 2023） |
| 3 | GPS 位置 | ⚠️ **对固定塘口无用** | 塘不会移动。它只是资产登记字段，不产生决策价值 |
| 4 | 据此指导撒多少粮 | ✅ **靠谱（带条件）** | 硬条件：必须做执行端标定、必须保留人工确认、必须接受 ±30–60% 精度天花板 |

**一句话**：用 ESP32 做「传感 + 决策 + 告警」非常靠谱；用它（或任何相机）做「数鱼」不靠谱。
**而好消息是——不需要数清鱼，也能把喂料这件事做好。**

## 二、本轮最硬的四条新证据（全部 A 级，可溯源）

### 1. ⭐ 「数鱼」比「估生物量」难得多的深层原因（我认为这是本轮最有价值的一条）

挪威三大生产商 **240 个网箱**实测（Aunsmo et al. 2013, *Aquaculture* 396-399:113-118）：
网箱级平均绝对生物量误差只有 **5.1%**——但同一份数据发现
**尾数误差与均重误差是反向关联的，两者在相乘得到生物量时互相抵消了。**

> 也就是说，产业界觉得「生物量估得还行」，有一部分是两个大误差的运气。
> **一旦你只要尾数，这个抵消就消失了，误差立刻暴露。**
> 这解释了为什么工业界宁可绕开「数鱼」，也不去硬解它。

这条直接回应了本项目第 1 轮对抗（重量 vs 尾数）中悬置的问题。

### 2. 中国最权威机构在真实土塘的最好成绩是 85–92%

- **中国水科院淡水渔业研究中心**（2026-07-14 官方发布）：声光融合 + 多源解算，
  江苏宜兴鳊、鲫基地验证，「养殖体量与密度的综合评估准确率达 **85%–92%**」，并自述「仍有较大优化提升空间」。
  ⚠️ 标注为 **B 级**：机构自报、未见同行评议、非逐尾计数。
- **华中农大**（高鑫等，水生生物学报 2026, 50(7): 072614，A 级）：透明度 12–15 cm 的浑浊池塘，
  动态声呐成像 **84.5%**。论文原话：「传统基于光学图像的机器视觉方法在此场景下难以奏效——
  即便辅以图像增强技术，鱼体目标仍难以稳定显现。」

### 3. 王春芳团队是「设计阶段就排除光学」，不是「失败后才转向」

这一条纠正了我们此前的表述。逐件核对 10 件授权专利后确认：

- 其传感器阵列的原理是**机械接触 / 压力 / 水流扰动 + 水听器 / 倾角**——
  **没有电场、没有电容**（此前 `自动喂食方案-决策建议.md` §1 的表述需据此修正）。
- 最硬的一手证据是专利 **ZL202110654210.2** 说明书自述其设计动机是主动避开「水下声、光、电」方案，
  理由是「**电气稳定性差、受混浊度影响大**」——**在设计阶段就排除了光学**。
- ⚠️ **一处归属更正**：`CN116541672B`（声学 + 水面波动）发明人是李路等，**非王春芳团队**。
  此前的转述有误，特此更正。
- ⚠️ 该团队全部专利与论文的目标都是「**饱食点 / 投喂量**」，**没有一件声称能反推尾数**。

### 4. ESP32 的边缘 AI 是「秒/帧」，不是「帧/秒」

乐鑫**官方** esp-dl COCO benchmark（A 级）：

| 模型 | ESP32-S3 上单帧耗时 | 帧率 |
|---|---|---|
| yolo11n @320 | **6,196 ms** | 0.16 FPS |
| yolo11n @640 | 26,000 ms | 0.04 FPS |
| MobileNetV2（分类） | 877 ms | 1.14 FPS |
| 人脸检测（单类小模型） | ~37 ms | 26.9 FPS |

且 GitHub 全量检索 `fish + detection + esp32` → **total_count = 5，全部 0 star**；
`fish + detection + tinyml` 与 `fish + detector + microcontroller` 均为 **0**。

> **「ESP32 做鱼类识别」零实证。** 建议直接写成方案红线（已写入交付文档与 Demo 网站）。

## 三、另外三条修正既有认知的量化结论

1. **生物污损有量化答案，且对鱼塘极为不利。** USGS TM1-D3 官方文件：
   营养富集且温度中高的站点「**可能需要每三天维护一次**」——中国南方精养土塘正是这一档。
   PLOS ONE 2022（13 万张图）实测：最短 **1 个月**内鱼类识别即不可行，中位耐久 **2 个月**，
   加防污船底漆**未能阻止**。另：**「蓝宝石防污」在文献中不成立**（蓝宝石只解决耐刮擦）。

2. **红外对射计数器失败的主因不是浊度，是无法分辨同时通过的个体。**
   即便装在鱼道里（开放土塘根本无法安装），Baumgartner et al. 2012
   （*J. Appl. Ichthyology* 28(4):531-536）实测中等通过率下**低估 56–84%**。

3. **溶氧曲线反推生物量不可辨识**：鱼仅占总耗氧约 **7%**，浮游生物 / 细菌占 **70–80%**，
   底泥 SOD 有 **16 倍**跨度。要从 93% 的背景里减出 7% 的信号——数值上不可能。
   （这是我此前列为「候选路线」的一条，现正式否决。）

## 六、诚实边界

**我没做 / 不能确定的：**

1. **声学设备价格完全空白**——厂商官网与政府采购平台均无公开可核实报价。
   交付文档中**未给任何推测价格**，相关项一律写「需询价确认」。
2. **「投喂量反推存塘量必然发散」的形式化定理未找到。** 该结论目前是控制理论推断
   （机制上是「没有量测输出的开环积分器」），**不是已证定理**。已在交付文档中明确标注。
3. **以生物污损为自变量的模型精度下降研究完全空白**——无法量化「脏到什么程度视觉就不可信」。
4. **中国水科院淡水中心的 85–92% 是 B 级**（机构自报、未见同行评议、无第三方复现），
   与华中农大 84.5%（A 级，有论文）**未混列**。
5. **所有硬件价格是工业 B2B 口径。** 淘宝 / 1688 / 京东详情页在本环境有登录墙，
   **个人小批量实际到手价可能高 20–100%**，已在手册封面显著标注。
6. **Demo 网站除证据条目外，全部数值为演示用模拟数据**，塘口档案、传感器读数、
   台账记录、节点状态均为编造，不可用于生产决策。已在页面与 README 双重声明。
7. **Word 文档未经真实 Word 渲染验证**：本环境 LibreOffice 转换失败，只做了
   zip 完整性 + OOXML 解析 + 结构断言（表格无全空、列数齐整、页脚域存在）。
   **建议用户在 Word 中打开后按 Ctrl+A → F9 刷新目录与页码。**
8. 三项行业误传已在调研报告中更正（OptoScale 不是「鱼游过的框架」、CageEye 不属 ScaleAQ、
   Aanderaa 无残饵产品）；《物联网卡安全管理办法》**未检索到该文件**、
   「运营商停开 NB-IoT」**无官方公告**、Air724UG 停产**无官方 EOL**——均保留为未证实。
