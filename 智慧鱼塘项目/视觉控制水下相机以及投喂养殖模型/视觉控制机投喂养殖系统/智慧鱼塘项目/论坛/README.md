## 一、项目背景

- **目标**：把鱼塘现有的「摄像头 + 脚本」链路，升级为**自动喂食**能力。
- **现状资产**（`录像与延时方案/`）：

| 文件 | 作用 |
|---|---|
| `萤石云-连接与长录像导出方案.md` | 连通性诊断、长录像导出三条路线（录屏/API/本地RTSP） |
| `延时方案.md` | 变化留图架构；API 链路；设备托管；4 路 NVR；launchd/cron |
| `record.sh` | 取 token → 取直播地址 → ffmpeg 录 N 秒 → 磁盘清理 |
| `download-recordings.sh` | 批量下载 SD 卡历史录像 |
| `api-test.sh` | 抓图 / 告警接口快速验证 |
| `监控网页.html` | 浏览器播放 + 逐路抓图 |
| `com.yutang.record.plist.example` | launchd 常驻定时 |

- **硬件前提**：萤石（EZVIZ）摄像头（疑似 4 路 NVR）；设备归属**好友账号**，正在走**设备托管**授权；
  Mac 常开可跑定时任务；**电脑与摄像头不在同一局域网**（隔互联网，这一条对方案影响很大）。
- **待决策的核心问题（用户提出）**：
  - **方案一**：拿鱼本身建模，按鱼的重量（多少斤）决定投喂量；
  - **方案二**：利用水面上当前摄像头获取的信息，进行微调。

## 三、痕迹规范（Trace Standard）—— 务必遵守

每位智能体的产出必须「留痕」，便于委托人与其他智能体追溯「谁做了什么、何时做的」。

1. **文件级**：文件顶部用 YAML frontmatter 声明作者与日期：

```yaml
---
作者: DeepSeek
日期: 2026-09-11
状态: 计划 | 草案 | 修订 | 定稿
关联: 鱼塘自动喂食
---
```

2. **文末签名**：每个文件末尾附一条可见签名：

```markdown
---
📌 痕迹 | @DeepSeek · 2026-09-11 · 本文由 DeepSeek 生成
```

3. **修订他人文件时**：不改写、**不删除**他人已有痕迹行，只在文末**追加**自己的一条，形成编辑链：

```markdown
---
📌 痕迹 | @DeepSeek · 2026-09-11 · 初稿（论坛搭建 + 方案调研任务书）
📌 痕迹 | @Claude   · 2026-09-11 · 补充 xxx
```

4. **关键结论级留痕**：正文里对"决策有影响"的结论，句末标 `〔@代号〕`，便于追责与回溯。
5. **数据/文献**：检索得来的数据必须带可点击 URL，并注明 `（检索：@代号, 日期）`。
6. **禁止**：编造论文标题、数字、价格。找不到就写「未找到可靠来源」。

## 四、沟通规则

1. **签到**：开工前在主论坛「留言记录」登记一行。
2. **认领**：在「任务看板」把状态改为 `进行中@代号` 即视为认领，先到先得；完成后改 `完成@代号`。
3. **防重复**：认领前先扫一遍看板，**同一任务不要两人并行做**——本项目人力有限，重复劳动是最大浪费。
4. **冲突**：不覆盖他人未完成的文件；要改他人内容，先留言说明，或另存新文件并说明关系。
5. **交付**：完成后在主论坛留言（含产出文件路径），并更新看板状态。
6. **礼貌**：彼此尊重产出；修改他人内容须在留言记录说明理由。
