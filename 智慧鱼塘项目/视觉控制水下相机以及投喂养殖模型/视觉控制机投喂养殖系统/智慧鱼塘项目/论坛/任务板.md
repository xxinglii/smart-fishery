## D. 明确不做（有证据支持否决）

| # | 不做的事 | 否决理由 |
|---|---|---|
| D1 | 塘面全景相机数颗粒 | **几何否决**：5m 高/1920px → 5.2mm/像素，3mm 颗粒仅 0.6 像素（门槛 >30 像素） |
| D2 | "投料量反推存塘量"自校准 | **正反馈发散**：过量投喂被读成"鱼变多了" |
| D3 | 水下相机估重 | 亚克力窗**每 3–4 天需清洗**；2003 年某系统误分类中 24% 来自维护不良 |
| D4 | 把 PAM/非光学传感器当作方案二的替代品 | **无池塘成功先例**：CageEye 自述不适合池塘/RAS；且"非光学"未锁定声学 |
| D5 | 金鱼方向全部产出（金鱼方案 v0.9/v1.1 + 红队报告） | **前提误识别**：2026-09-11 用户确认品种为**食用鱼**；文件已归档，仅红队方法论批评（状态辨识/可用性偏差/LLM 幻觉）随二期移植（见 v2 §10）〔@Claude 前提修正通告〕 |
| D6 | **摄像头数鱼**（本轮新增，判定升级为「有实测数字否决」） | **土塘实测数字否决**：纯光学池塘公开最好成绩 **mAP 38.93%**（DePondFi'23，15 队参赛）；加声学融合，中国水科院淡水中心真实土塘仅 **85–92%** 且是「体量/密度」非逐尾；华中农大声呐 **84.5%** |
| D7 | **ESP32 端侧跑鱼类识别**（本轮新增） | **乐鑫官方 benchmark 否决**：yolo11n@320 在 ESP32-S3 上 **6,196 ms/帧（0.16 FPS）**；且 GitHub 全量检索 `fish+detection+esp32` 仅 **5 个仓库、全部 0 star**——零实证 |
| D8 | **水下相机长期值守**（本轮新增，D3 的量化升级） | **维护频次否决**：USGS TM1-D3 官方——营养富集温水体「可能需要**每三天**维护一次」；PLOS ONE 2022 实测 1–2 个月内识别即不可行，防污漆无效 |
| D9 | **红外光幕 / 对射计数**（本轮新增） | **双重否决**：开放土塘无强制通道，物理上无法安装；即便装在鱼道里，Baumgartner 2012（*J. Appl. Ichthyology* 28(4):531-536）实测中等通过率下**低估 56–84%** |
| D10 | **溶氧曲线反推生物量**（本轮新增，原为候选路线） | **不可辨识**：鱼仅占总耗氧 ~7%，浮游生物/细菌占 70–80%，底泥 SOD 有 16 倍跨度——要从 93% 背景中减出 7% 信号 |
| D11 | **「蓝宝石防污」类伪需求**（本轮新增） | 文献中不成立：蓝宝石（Mohs 9）只解决耐刮擦，**不防污** |
