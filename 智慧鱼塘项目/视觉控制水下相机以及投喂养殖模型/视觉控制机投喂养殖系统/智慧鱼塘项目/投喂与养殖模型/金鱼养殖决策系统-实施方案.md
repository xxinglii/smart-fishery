## 1. 四个坏消息（请先看完这段再决定要不要做）

### 坏消息一：国家标准里，金鱼压根不看体重 ⭐ 最硬的一条

**农业农村部行业标准 SC/T 5707-2018《金鱼分级 和金》**的四维指标是：

| 指标 | 要求 |
|---|---|
| 体型比例 | 体高 / 体长 ≥ 0.35 |
| 尾鳍 | 尾鳍长 / 体长 ≥ 0.28 |
| 色彩 | 按品种色系评定 |
| 对称性 | 左右对称、无残缺 |

**测量工具是游标卡尺。全文零次提到体重。**

→ 而市场也按"**尾**"和"**cm**"计价（泰狮 0.55 元/尾；珍珠金鱼按 9–10cm 标规格），
池塘产出描述是"亩产 **12 厘米以上**大规格金鱼近万**尾**"。

**致命推论**：收益 = Σ(尾数 × 品级单价)，**与重量无单调关系**。
**催肥会导致体型走样 → 品级暴跌 → 增重即贬值。**

> ⚠️ **任何以"重量"为核心的目标函数，都会系统性地引导养殖户做破坏自身价值的操作。**
> 这是本方案与常规"水产养殖决策系统"最根本的分歧点。

来源：[SC/T 5707-2018 标准信息](https://www.antpedia.com/standard/1527373990-10.html) ·
[安徽农网·精养观赏鱼](https://www.ahnw.cn/nykj/Content/da739892-b155-45c9-b995-11227d90f151)

### 坏消息二：状态不可辨识——产量预测不是"难"，是"**无解**"

预测产量 = 求解 `dN/dt`（死亡）和 `dL/dt`（生长）。这需要：
- **初始条件**（放养日期、尾数、规格、品种）
- **驱动变量时序**（水温、溶氧）

**而你的 4 项输入里**：
- 摄像头 → 是"果"（现象），不是原因
- 重量、数量 → 是"果的快照"
- 投料机 → 是执行器

> **没有一个是初始条件，没有一个是驱动变量。**

**观测等价性反例（这一条最要命）**：
```
系统看到：10000 尾、均重 20g
可能 A：30 天前放养 15000 尾 1.5cm 苗，成活率 67%
可能 B：30 天前放养 10500 尾 5cm 苗，成活率 95%
→ 两者下月的产出规格分布完全不同，但系统看到的输入一模一样。
```

**这就是状态不可辨识。** 系统会输出带**虚假精确度**的数字（"预计出塘 8300 尾"），
而真实误差带是 3000~15000。

> **不可辨识系统的输出，比"不知道"更危险——因为它伪装成知道。**

### 坏消息三：金鱼长得极慢，"月产量"这个概念要重新定义

- 普通金鱼**一年约长 8 厘米，一个月不到 1 厘米**；鎏金等快品种一年约 12 厘米
- 从 1.5–2.0 cm 鱼苗到 **12 cm 商品规格，约需一年**

→ **本月和下月能上市的鱼，生物学上几乎是同一批。**
所以"月产量"不是每月自然产出，是"**哪一批到规格了**"——**批次事件，不是连续流**。

### 坏消息四：这是一个**需求侧受限**的生意

观赏鱼是**需求侧受限**（销路、品相偏好、节庆档期），不是产能受限。
**只优化供给侧产量 = 高效地生产一堆卖不掉的鱼。**

→ 所以"产量规划"的正确问法可能不是"我能产多少"，而是"**我该在什么时候、产什么规格的多少尾**"。
这个问题需要**销售数据**，而它不在你的 4 项输入里。

## 1.5 两条反直觉的经营结论（可能比软件本身更值钱）

> 这两条来自金鱼养殖专项调研，**都是实测数据，不是推断**。它们改变的是经营策略，不是算法。

### 结论一：「稀养」比「密养」更赚钱 ⭐

**草金鱼池塘养殖密度试验**（朱建辉等，《现代农业科技》2021(17):203-205，已获取全文）：

| 指标 | 4 万尾/亩 | 8 万尾/亩 | 变化 |
|---|---|---|---|
| 亩产 | 427 kg | 543 kg | **+27%** |
| 成活率 | **86.5%** | 75.6% | −10.9 pt |
| 规格 | 80 尾/kg | 110 尾/kg | 变小 |
| **观赏鱼销量占比** | **87%** | **42%** | **−45 pt** |
| **亩利润** | **4745 元** | **3827 元** | **−19%** |

> **食用鱼那套"密度↑ → 产量↑ → 利润↑"的线性逻辑，在金鱼上彻底失效。**
> 密度翻倍，亩产确实涨了 27%，但**能卖上价的鱼从 87% 腰斩到 42%**，结果**利润反而降了 19%**。
>
> **对一个"算产量"的系统来说，这是一个必须内建的警告：**
> **只优化公斤数的系统，会建议你加密——然后让你少赚钱。**

### 结论二：分拣/分级是**利润中心**，不是辅助环节

**北京市地方标准《宫廷金鱼分级技术规范》编制说明**（官方文件）原文：

> 同一品种、**同样规格**，形态完美与有缺陷个体**价差可超过 10:1**；
> "一批各等级混合的金鱼，价格往往以**品级最低**的个体为代表确定……有时甚至以'饲料鱼'的价格出售。"

→ **混级出货 vs 分级出货，同一批鱼收入可差数倍。**
→ **你这套系统里目前没有"品级分布台账"——但它才是利润的真正来源。**

> **这是对"收益 = 尾数 × 品级单价"这一模型的官方背书**（见坏消息一）。
> **也意味着：系统若要真正创造价值，必须有"品级"这个维度；否则它算得再准，算的也是错的指标。**

## 2. 需求拆解

### 需求一：产量规划

```
① 存塘多少尾？      ← 放养数 − 累计死亡 − 累计销售 ± 分池     【台账】
② 多少尾达标？      ← 体长分布 × 商品门槛（如 ≥12cm）        【抽样 + 品级标准】
③ 这个月多少达标？  ← 批次放养日期 + 生长曲线                 【台账 + 模型】
```

**①② 靠台账，③ 靠模型。台账是地基。没有台账，模型无从标定。**

> ⚠️ 但请注意坏消息二：**在初始条件缺失时，③ 的输出只能是区间，不能是点值。**

#### ⭐ 但"月产量"这个问题，更该问的是"什么时候卖"

金鱼养殖专项调研带回一条**改变经营逻辑**的事实——**金鱼有明确的价格窗口，且全年断档近半年**：

| 时段 | 市场状态 |
|---|---|
| **8 月 — 次年 1 月** | **主季** |
| 4 — 7 月 | 反季节（冬棚），可上市 |
| **2 — 6 月** | **断档** |

- **元旦起进入旺季，农历小年前后一个月为峰值，销售额约为平时 3 倍、占全年约 20%**，春节前售罄。
  （福州市海洋与渔业局 2024-02-04；福州晚报 2026-02-13）

> **推论：每月出塘量应按价格窗口排"双峰"，不能按月平均分配。**
> 所以"一个月能产多少鱼"的正确形式是：
> **"为了打到小年那波 3 倍价，我该在哪个月放苗、放多少？"**
>
> **这是把"产量规划"从一个预测问题，变成一个排产优化问题——后者才真正可解。**
> 〔@DeepSeek，此推论基于上述价格窗口事实〕

### 需求二：科学喂养

```
W_day = N × w × r_base × f_T × f_DO × f_天气
```
- `N` 存塘尾数、`w` 抽样均重 → 生物量
- `r_base` 基础投饲率（金鱼约 3%，**待本塘标定**）
- `f_T` 水温修正、`f_DO` 溶氧修正、`f_天气` 天气修正

```
W_meal = W_day / n          （金鱼建议 n = 4 餐/天）
T_秒   = W_meal / v         （v = 投料速率，必须现场标定）
```

## 3. 系统架构

```
┌─ 交互层（LLM 在这里，且只在这里）──────────────────────┐
│  · 语音/自然语言录入台账                               │
│  · 把确定性模块算出的数字翻译成人话（并说明理由与区间） │
│  ⛔ 红线：LLM 无权生成任何数字                          │
└──────────────────────┬─────────────────────────────────┘
                       ▼
┌─ 决策层（确定性、可解释、可回测）──────────────────────┐
│  ① 投喂建议（区间 + 安全钳制）  ② 积温-生长外推         │
│  ③ 环境硬开关/告警              ④ 台账统计              │
│  ⑤ 置信度分层（区间，不给点值）                         │
└──────────────────────┬─────────────────────────────────┘
                       ▼
┌─ 数据层（四本账是核心，传感器是辅助）──────────────────┐
│  ★ 批次台账  ★ 投喂记录  ★ 死亡记录  ★ 出塘/销售记录   │
│  + 水温 / 溶氧传感器                                   │
│  + 萤石视频（仅定性事件：浮头、死鱼、水色突变）         │
└────────────────────────────────────────────────────────┘
```

### ⛔ 三条架构红线

1. **LLM 不进数值决策回路，无权生成任何数字。** 只做录入、翻译、解释。
2. **不做无人确认的自动投喂决策。** 建议必须经 APP 人工确认后执行。
3. **不给点估计。** 所有预测输出必须是区间 + 假设。

### 为什么是这三条红线（证据）

**关于 LLM 做时间序列预测**：已有实证——开源预训练时间序列模型平均只达到弱基线的 **59.5%**。
论文原话："In real-world settings, the ground-truth relation function *f* is typically unknown"。
养殖场**永远不知道真实的 f，因此连自己有没有幻觉都无法测量**。

**关于小样本**：小样本下**改进 XGBoost 优于神经网络**。
且微调小模型 = 必然过拟合 + **灾难性遗忘**，恰在养殖场最需要的"没见过的异常情景"上表现最差。

**关于"自信地错"**：LLM 无校准置信区间、不保证单调性、**不会说"我不知道"**。
冷启动时它会用通用先验填补空白，输出语气笃定的具体数字。
**生产系统最危险的失败不是报错，而是自信地错。**

来源：[时间序列基础模型幻觉研究](https://ar5iv.labs.arxiv.org/html/2508.00881) ·
[小样本XGBoost对比研究](http://hyyysci.com/cn/article/pdf/preview/10.14012/j.cnki.fjsc.2023.05.002.pdf)

## 4. 数据：能力分级与必须新增项

### 4.1 现有 4 项条件的真实能力

| 级别 | 数据源 | 能回答 | 不能回答 |
|---|---|---|---|
| **C 级（仅定性）** | 萤石视频 | 浮头、死鱼漂浮、水色突变、摄食水面活动强度 | ❌ 计数 / 测长 / 测重 |
| **A 级（进模型）** | 鱼的重量 | 投喂量（**且仅此**） | ❌ 产量、品级 |
| **执行器** | 自动投料机 | 能"投" | ❌ 不知投了多少（容积式无称重） |
| **A 级（进模型）** | 金鱼的数量 | 存塘尾数（**但会变**） | ❌ 单独不够 |

> **⚠️ 一个必须点破的逻辑漏洞：可用性偏差。**
> 摄像头是唯一能自动、连续、零人力采集的信号，于是很容易被当成核心数据源。
> **但"最容易采集" ≠ "信息量最大"。**
> 若架构由最弱的信号主导，就是**在路灯下找钥匙**——不是因为钥匙在那儿，而是因为那儿亮。

**硬件也不匹配**：萤石是户外安防相机（IP66/IP67 = 短时浸泡，**非连续水下耐压**），
**无水下折射校正、无双目标定、无测距**，像素尺寸无法反推真实体长。

### 4.2 必须新增的输入（按重要性排序）

| # | 输入 | 为什么必需 | 成本 |
|---|---|---|---|
| **1** | **批次台账**（放养日期/尾数/规格cm/品种/苗源） | **唯一初始条件**，没有它一切免谈 | **零**（记录习惯） |
| **2** | **出塘/销售记录**（日期/尾数/体长分布/品级/单价/死淘） | **唯一 ground truth** | **零**（记录习惯） |
| **3** | **投喂记录**（时间/饲料/量/摄食完成时间） | 学习信号 | **零**（记录习惯） |
| **4** | **死亡淘汰记录** | 修正存塘数 | **零**（记录习惯） |

| 10 | 品级价格体系 | 收益计算 | 零 |
| 11 | 图像结构化标注 | 视觉辅助（远期） | 人工 |

> **🔑 关键洞察：第 1、2、3、4 项都是零硬件成本的"记录习惯"问题，不是技术问题。**
> **真正的瓶颈不是模型，是数据采集纪律。**

## 5. 核心算法（含安全钳制）

### 5.0 ⭐ 金鱼真实投喂参数（本次调研的最大收获，可直接落地）

**投饲率有明确拐点：3% 体重/日，超过就不划算。**
Belsare & Dhaker (2019), *Indian J. Anim. Res.* 53(1):94-98（同行评议，AGRIS 收录）：
1.66 g 金鱼幼鱼，4×4 设计（2/3/4/5% BW/day × 1/2/3/4 餐），
**最优 = 3% BW/day + 4 餐/日；超过 3% 后 SGR / FCR / PER 同时下降。**

> → **自动投料机的上限应设在这个拐点，而不是"能吃就多喂"。**
> 这一条同时给了我们**安全钳制的物理上限**：`W_day ≤ 3% × B`（旺季除外，见下表）。

**分季节日投饵率（草金鱼池塘实测，朱建辉等 2021《现代农业科技》2021(17):203-205）**：

| 时段 | 餐次 | 日投饵率 |
|---|---|---|
| 5 — 7 月 | 2 次/日 | **2.5% ~ 3.5%** |
| 7 月 — 8 月上旬 | 3 次/日 | **4% ~ 5%** |
| 8 月中 — 9 月底 | 2 次/日 | **3% ~ 4%** |
| 10 月起 | 2 次/日 | **1.5% ~ 3.0%** |

> **这是本次找到的最接近"金鱼投喂表"的东西——是实测值，不是通用食用鱼表的套用。**

**地方标准规则（DB4113/T 037-2023，南阳）**：
水温 **10℃ 起投**；10~15℃ 每天 1~2 次；旺季每天 4 次（**7-8 / 10-11 / 13-14 / 16-17 时**）；
每次 **7~8 分饱，以 1 小时内吃完为准**；配合饲料**蛋白 >36%**（草金鱼养成实测 30% 即可）。

**体长 ↔ 体重锚点**（王凡等 2010，《水产科学》29(6):369-371）：
**体长 6.50±0.50 cm ↔ 体重 9.12±0.45 g**（金鱼鱼种）。
→ **可用于把"鱼的重量"数据换算成规格**，这是你那 4 项条件里"重量"最有价值的一个用法。

### 5.1 投喂建议：**区间 + 安全钳制 + 人工确认**

```
建议区间 = [W_low, W_high]  ← 由投喂模型给出，带不确定性
最终执行 = 人工确认后的值
```

**⚠️ 不对称风险原则（本方案的安全核心）**：

> **投喂不足只是"长得慢"（温和的错）；投喂过量可能"一夜死塘"（致命的错）。**
> 且**过量投喂是自催化灾难**：残饵 → 耗氧 + 氨氮飙升 → 水质崩溃 → 缺氧泛塘。

**因此安全钳制必须是不对称的**：

| 条件 | 允许的操作 |
|---|---|
| 水温 > 32℃ / 闷热低压 / 摄食时间变长 | **只允许减，不允许增** |
| 任何情况 | **不超过人工历史上限的 110%** |
| 任何情况 | **不超过当季投饲率上限（见 §5.0，常规 3%，旺季 5%）** |
| 溶氧 < 3 mg/L | **建议停喂，并联动增氧机** |
| 系统不确定 / 数据缺失 | **保守默认：少喂** |

> **而这里有一个必须立刻补上的致命盲区**：
> **你现在没有任何溶氧传感器——恰在"错得致命"的那个方向上完全盲。**
> 这是全方案性价比最高的一笔投入。

**FAO 有鲤鱼苗高血氨氮自体中毒的案例**，可作警示：
<https://www.fao.org/fishery/docs/CDrom/aquaculture/a0845t/volume2/docrep/field/003/ac160e/AC160E05.htm>

### 5.2 生长与产量：积温外推 + 保守区间

```
体长(t) = f(积温, 累计投喂, 初始体长)    ← 本塘抽样数据拟合
当月可上市 = Σ_批次 ( 放养尾数 × 成活率 × 规格达标率 × 当月达标比例 )
```
**输出必须是区间**，并附明假设（成活率取值、生长曲线来源）。

### 5.3 执行端标定

`v = 投料速率 (kg/秒)` 必须现场标定，且随**料位/电压/粒径**变化。
**建议 3×3×3 正交实验**（粒径 × 料位 × 电压），每组合 3 次取均值。
**这是全网找不到现成数据、但你这套系统非做不可的一件事。**

### 5.4 KPI 单位

> **所有产量类指标，单位必须是「尾数 × 体长规格档 × 品级」，禁用公斤。**
> 这是坏消息一的直接推论。

## 6. 实施路线

| 阶段 | 周期 | 做什么 | 承诺什么 | **不承诺** |
|---|---|---|---|---|
| **MVP-0**<br>换数据 | **2–4 周** | 四本账强制记录（批次/投喂/死亡/出塘）+ 装水温溶氧 | **投喂记录完整率 ≥95%** | ❌ 任何智能建议 |
| **MVP-1**<br>能算 | 2–4 周 | 台账系统 + 投喂区间建议 + 环境硬开关 + 告警 | A 档：记录准确、建议有据 | ❌ 省料百分比 |
| **MVP-2**<br>能估 | 1–2 月 | 积温-生长外推 + 产量**区间** | B 档：带区间与假设 | ❌ 点预测 |
| **MVP-3**<br>能看 | 待定 | 视频辅助（浮头/死鱼/水色事件；摄食趋势→停投） | 事件识别准确率 | ❌ 计数/测长/测重 |

### 🚦 上线门槛：必须做回顾性 backtest

> **用过去 1–2 年的出塘记录离线回测。没有 backtest，不上线。**
> 这是唯一能在"没有实时 ground truth"的情况下验证模型的方法。

### 验收指标怎么定

> **不要写"省料 X%"**——单塘没有对照组，这个数字**在数学上无法测量**，敢承诺的一定在编。
>
> 正确指标：
> - MVP-0 → **投喂记录完整率**
> - MVP-1 → **建议采纳率** + 异常事件数（浮头、缺氧、死鱼）
> - MVP-2 → **区间命中率**（实际出塘落在区间内的比例）
> - 全程 → **防死鱼成功次数**（这是最高价值功能）

## 7. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 网页 + 微信小程序 | 手机上就能用 |
| 后端 | Python（FastAPI） | 与数据分析同语言 |
| 数据库 | SQLite → PostgreSQL | 单场起步 SQLite 足够 |
| 模型 | **积温生长模型 / 投料表插值 / 贝叶斯状态估计（自带置信区间）/ XGBoost** | **小样本友好、可解释** |
| LLM | 云端 API，**仅交互层** | 先不微调 |
| 传感器 | **水温 + 溶氧（荧光法）** | **必需，溶氧是防死变量** |
| 执行 | 现有投料机 + 智能插座/继电器 | 先记录时长；计量是后续 |

---

## 8. 明确不做的事

| 不做 | 理由 |
|---|---|
| **微调 LLM 做数值预测** | 实证：开源时序模型仅达弱基线 59.5%；且 ground-truth f 未知，**连幻觉都无法测量** |
| **以重量为核心状态量** | **SC/T 5707-2018 分级标准零次提到体重**；催肥→体型走样→贬值 |
| **摄像头做计数/生物量** | 硬件无折射校正/双目标定/测距；IP66/67 非连续水下耐压 |
| **月产量的点估计** | 状态不可辨识；只能给区间 |
| **无人确认的自动投喂** | 风险不对称；且系统连"今天水温31℃所以减料"都解释不了 |
| **承诺"省料 X%"** | 单塘无对照组，数学上无法测量 |
| **只优化供给侧产量** | 需求侧受限生意，会高效生产卖不掉的鱼 |

## 10. 需要你确认的 6 件事

1. **"金鱼"确认吗？**（若为语音输入误识别，整个方案要重写）
2. **"鱼的重量"怎么测的？** 抽样还是估算？多久一次？
   ⚠️ 若它是**卖鱼过秤的累计值**，那它是**产量结果**，不是状态变量。
3. **"金鱼的数量"是放养数还是现存塘数？** 有台账吗？多久盘点一次？
   ⚠️ 若靠**每月人工盘点**，那是稀疏低质量标签，**不能做实时决策**。
4. **有没有历史出塘/销售记录？**（决定 MVP-2 能否做、backtest 能否做）
5. 塘的面积、水深、放养密度、是否混养、**主养品种（和金？草金？兰寿？泰狮？）**
6. **有没有增氧机？有没有溶氧传感器？**（没有溶氧 = 在最致命方向上盲）

## 11. ⛔ 数据的空白清单（防猜测值）

> 以下是金鱼专项调研**明确未找到可靠来源**的条目。
> **系统的设计原则是：空白就是空白，宁可显示"无数据"，也不许用食用鱼通用值或文献推测值填充。**
> 一旦系统开始"合理推测"，它就变成了一个自信的胡说机器。

| 空白项 | 状态 | 影响 |
|---|---|---|
| 金鱼**专用投饲率表**（水温 × 规格矩阵） | ❌ 不存在 | 只能用 §5.0 的分季节实测值替代 |
| 金鱼 **SGR 典型值** | ❌ 无来源给出数值 | 生长外推的不确定性来源 |
| 草金鱼/狮子头/龙睛/兰寿**品种间定量生长对比** | ❌ 无 | 跨品种不可迁移 |
| 金鱼 **FCR 数值** | ❌ 只有"3% 时最优"这一结论 | 无法做成本精算 |
| **精品率/品相率的行业统计基准** | ❌ **全行业最大空白** | ⭐ **也是本系统最有价值的自建指标** |
| 水花 → 夏花成活率的权威统计 | ❌ 无 | 批次台账需自行积累 |
| **官方逐月出塘量分配表** | ❌ 只有上市窗口的定性描述 | 排产靠自建数据 |
| 氨氮对金鱼的毒性阈值 | ❌ 未取得 | 水质告警缺一条阈值 |
| DB11/T 924-2022、SC/T 5706-2018 正文 | ⚠️ 付费，只拿到目录与术语 | 关键数值缺失，建议采购 |

> **📌 一条重要的反向发现**：金鱼亚硝酸盐 96h LC50 = **341.47 mg/L**，安全浓度 **34.15 mg/L**，
> 而生产运行值约 **0.1 mg/L**——**差 340 倍**。
> → **金鱼死亡的主因更可能是应激 / 寄生虫 / 细菌病，而不是亚硝酸盐中毒。**
> 这提示告警系统的优先级排序：**溶氧 > 病害 > 氨氮/亚硝酸盐**。

## 附：这份方案是怎么被改出来的

本方案经历 **5 轮自我对抗 + 1 轮独立红队评审 + 1 轮金鱼专项调研**：
**我最初的判断几乎被改了个遍。**

| 我最初以为 | 最终结论 |
|---|---|
| 重量是核心状态量 | **SC/T 5707-2018 根本不看体重**；KPI 改用「尾数 × 体长 × 品级」 |
| 冷启动可以靠模型外推 | **状态不可辨识**，只能给区间 |
| LLM 可以辅助决策 | **LLM 无权生成任何数字** |
| 摄像头是核心数据源 | **可用性偏差**——最容易采集 ≠ 信息量最大 |
| 先做智能建议 | **先记一年账** |
| 投饲率"约 3%，待标定" | **3% 是实测拐点**，超过则 SGR/FCR/PER 全面下降；且有分季节实测表 |
| 产量↑ 就利润↑ | **密度翻倍 → 亩产 +27% → 利润 −19%** |
| 收益 = 尾数 × 单价 | **同规格价差可超 10:1，分拣才是利润中心** |

> 红队的一句话总结，我完全接受并引用：
> **"这不是数据不够，这是方程无解。"**
>
> 但**方程无解不等于事情不能做**——把目标从"AI 预测"降级为"台账 + 告警 + 区间建议"，
> 它立刻就变成一个**扎实、可交付、有复利**的系统。
> **而且那四本账，今天就能开始记，零成本。**
