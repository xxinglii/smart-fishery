## 0. 一句话方法论

> **生物量定"量"（基准投喂量），摄像头定"停"（实时闭环），水温/溶氧定"能不能投"（硬约束）。**

三个引擎各管一件事，组合成一个投喂决策闭环。单独依赖任何一个都会失效。

---

## 1. 项目目标

- **自动化按需投喂**：替代"定时定量 + 凭经验"，让投喂量跟随鱼群真实食欲浮动。
- **降本增效**：饲料占养殖成本 **50–70%**，是最大的单项成本。目标指标：
  - 饲料系数（FCR）下降 **≥ 8%**（行业平均）；
  - 水面残饵率 **< 5%**（渔机所验收指标）；
  - 饵料利用率提升 **≥ 15%**（浙大宁波理工"渔智联"实测）。
- **省人力、可追溯**：远程/群体管理，投喂记录数字化，便于对账与复盘。

## 2. 核心设计原则

1. **组合而非单选**：生物量模型给出"投多少"的起点，摄像头给出"何时停/何时加"的反馈，二者缺一不可。
2. **先简单后智能**：先落地"水温 + 投喂表 + 捞样估重"（无 AI 也能跑），再逐步叠加摄像头闭环、生物量自动化。
3. **环境是硬约束**：鱼是变温动物，温度直接决定食欲；低溶氧、高温/低温、病害期必须强制减喂或停喂——这是投喂表的明确要求，不可省。
4. **边缘部署、低成本**：模型轻量化，算力下沉到塘口，避免对云端实时网络的强依赖。

## 3. 系统总体架构

```
┌─────────────────────────── 感知层 ───────────────────────────┐
│  水面摄像头(水花/残饵/聚集)  水温/溶氧/pH 传感器   捞样/估重   │
│  可选: 水下摄像头 / 声呐(生物量)                              │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌─────────────────────────── 决策层（边缘盒子）────────────────┐
│  ① 生物量估计模块   ② 投喂基准量计算   ③ 行为识别模块        │
│  ④ 环境硬约束       ⑤ 投喂决策引擎                            │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌─────────────────────────── 执行层 ───────────────────────────┐
│  投饵机(继电器/变频控制)     ──▶  鱼塘                          │
│  反馈：实际投喂量、投喂记录 ──▶ 云端/手机端                    │
└──────────────────────────────────────────────────────────────┘
```

## 4. 关键模块设计

### 4.1 生物量估计模块（方案一的"重量"从哪来）

| 方案 | 精度 | 成本 | 适用阶段 |
|---|---|---|---|
| **A. 捞样估重**（抽样称重 × 存塘量推算） | ±8–12% | 极低（人工） | Phase 1（起步） |
| **B. 水下相机 / 立体视觉估重** | 平均误差 ~4.1%（三文鱼实测） | 中 | Phase 3（进阶） |
| **C. 声呐（回声探测/3D 声呐）** | 覆盖全塘、不依赖水体清晰度 | 高 | Phase 3 备选 |

- **初期推荐 A**：最快落地，配合"生长模型 + 投喂表"做日增重外推，在两次捞样之间平滑生物量曲线。
- 生物量模型：`B(t+1) = B(t) × (1 + 日增重率(T)) − 死亡损耗`，其中日增重率由温度与规格查品种生长数据。

### 4.2 投喂基准量计算（投喂表，方案一核心）

```
日基准投喂量 W_base (kg/day) = B (kg) × r / 100
其中 r = 投喂率 (%BW/day)，查【品种专属投喂表】，自变量 = (鱼规格, 水温)
```

**关键规律（必须进模型）**：
- 鱼越小投喂率越高：幼鱼可达 **7.5% BW/day**，成鱼降到 **0.5–1%**。
- 温度偏离最适区间投喂率骤降：如罗非鱼 0.5–4g 规格，**4.0%（18℃）→ 6.0%（29℃）→ 5.5%（33℃）**；银鲈成鱼 **0.5%（15.6℃）→ 3.0%（24.1℃）**。
- 投喂表为经验基准，**必须叠加实时反馈修正**（这正是方案二的价值）。

> ⚠️ 品种未定之前，本模块只能写成"查表"占位——**具体投喂表参数必须在确定品种后填入**。

### 4.3 水面摄像头行为识别模块（方案二核心）

水面摄像头能可靠观测到的三个信号，是"该不该停"的直接依据：

| 信号 | 含义 | 技术路线 |
|---|---|---|
| **漂浮残饵** | 直接指示"喂多了" | 改进 YOLOv5/v8 小目标检测，残饵率 → 停投阈值 |
| **进食水花 / 波纹** | 指示活跃度/食欲 | 双目/深度相机 + 光流，量化为"水花面积" |
| **鱼群聚集度 / 上浮** | 指示食欲强弱 | 目标检测 + 密度统计 |

- **模型选型**：YOLOv8 改进系（轻量化模块 RepSELAN/SPPSF 可减参 31%、算力 26%），可部署到边缘设备（如 RK3588/Jetson Orin NX）。
- **精度参考**：残饵识别 90%+；水花法 mAP 88.2%、精确率 93.2%；饱食度分类 98.1%。

### 4.4 环境传感器模块（硬约束）

- **水温**：投喂表的第二自变量，必须实时。
- **溶解氧**：低溶氧不投喂（闷热、阴天、藻华期）。
- **pH / 氨氮（可选）**：病害与水质预警。

### 4.5 投喂决策与执行模块

- 决策引擎输出"继续 / 减速 / 停止"三态，控制投饵机（继电器通断或变频调速）。
- 投喂记录（时间、量、环境参数、摄像头判定）回传云端/手机端，可追溯。

## 5. 投喂决策算法（伪代码）

```
每日决策：
  输入：B(生物量kg), T(水温℃), DO(溶氧mg/L), 品种投喂表 f(size,T)→r
  1) 基准量：W_base = B * r / 100
  2) 环境硬开关：
       if DO < 阈值   or  T < 下限  or  T > 上限  or  病害期:
           W = 0;  return  # 强制停喂
  3) 分餐：按投喂频率 n，每餐 W_meal = W_base / n

每餐实时闭环（摄像头）：
  边投边观测 p_uneaten(残饵率) 和 a(活跃度/水花强度)
  loop:
       if p_uneaten > P_stop(≈5%):  停投          # 剩料即停
       if a 骤降（饱食信号）:        停投          # 吃饱即停
       if 投喂量达到 W_meal 上限:   停投          # 量控兜底
  # 记录本餐实际量 W_actual，次日基准量按残饵情况微调
```

**三个停投条件分别对应**：残饵（喂多了）、饱食行为（吃够了）、上限（防模型漂移）。三者"或"关系，谁先触发谁停。

## 6. 硬件选型清单（示意）

| 部件 | 选型方向 | 说明 |
|---|---|---|
| 投饵机 | 电动投饵机（可联网/继电器控制） | 支持远程启停、变频调速更佳 |
| 水面摄像头 | 4K 全局快门网络相机 | 看水花+残饵，120Hz 高速成像更佳 |
| 水下相机 | 带补光灯防水相机 | Phase 3 估重/残饵兜底 |
| 声呐（可选） | 回声探测 / 3D 声呐 | 浑浊水体估重、全塘覆盖 |
| 水温/溶氧 | 荧光法溶氧传感器 + 温度一体 | 溶氧是硬开关，不能省 |
| 边缘算力 | RK3588 / Jetson Orin NX | 跑轻量化检测模型 |
| 联网 | 4G / NB-IoT / LoRa | 塘口常无 Wi-Fi |

## 7. 分阶段实施路线图

| 阶段 | 内容 | 周期 | 产出/效果 |
|---|---|---|---|
| **Phase 1** | 水温传感器 + 品种投喂表 + 捞样估重 + 每日基准量（小程序/表格） | 1–2 周 | 无 AI，已优于"定时定量" |
| **Phase 2** | 水面摄像头 + 残饵/水花检测 + 自动停投闭环 | 1–2 月 | 残饵率 <5%，省料 8–10% |
| **Phase 3** | 水下相机/声呐估重，替换捞样，全自动 | 3–6 月 | 真正"无人"投喂 |

## 8. 数据采集与模型训练

- **Phase 2 前**：采集本塘视频，标注"残饵 / 水花 / 聚集"三类目标，构建数据集（每类 2000+ 帧起步）。
- **饱食度标签**：做"饱食实验"生成定量标签（区别于主观强/中/弱）。
- **迭代**：先跑公开预训练权重微调，再按本塘环境（浑浊度、光照、昼夜）继续训练。

## 9. 成本与效益估算（示意，需按塘规格校准）

- 饲料占成本 50–70%；AI 动态投喂 FCR 从 1.32→1.19 可省料 **9.8%**。
- 假设年饲料成本 10 万元，省 8–10% 即 **0.8–1.0 万元/年**；设备一次投入（投饵机 + 摄像头 + 传感器 + 边缘盒）数千到数万元量级，回本周期 **1–3 年**（规模越大越快）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 浑浊水体 / 夜晚残饵看不清 | 白天闭环 + 补光灯；浑水塘用声呐或水下相机兜底 |
| 品种未定导致投喂表空转 | **开工前必须定品种**，先锁定投喂表 |
| 生物量估计误差大 | 捞样打底 + 生长模型外推 + 定期校正 |
| 边缘算力不足/成本高 | 轻量化模型（可减参 30%+），按需选算力档 |
| 传感器故障/漂移 | 硬开关冗余：环境数据异常默认保守（少喂/停喂） |

## 11. 待确认事项（开工前必须定）

1. **养殖品种**（决定投喂表参数、残饵检测难度、生长模型）——**最高优先级**。
2. 塘口面积、数量、养殖密度、现有设备（有无摄像头/投饵机/增氧机）。
3. 目标预算与期望回本周期。
4. 是否有网络覆盖（决定边缘 vs 云端方案）。
