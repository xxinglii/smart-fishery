# 鱼塘摄像头延时（变化留图）方案

> 目标：用尽量少的存储，记录鱼塘状态**有变化的时刻**；没变化就不存。
> 原则：**事件优先，定时兜底**。不建议上 NVR（NVR 会持续录像，与目标相反）。

## 一、总体架构

```
摄像头(移动/人形侦测已开启)
    │
    ├─① 产生告警事件 ──► 萤石开放平台告警接口 ──► 拉取 alarmPicUrl ──► 存图
    │                                                        （有变化）
    │
    └─② 长时间无告警 ──► 低频巡检抓图 (device/capture) ──► 图片差分
                                                              │
                                              差异显著 ──► 存图
                                              无差异   ──► 丢弃
```

- **白天**主要走 ①：只在有人形/移动/车辆事件时取图，平时几乎不产生图片，对电池设备尤其友好。
- ② 是兜底：连续 N 分钟（建议 30~60）没有事件，就抓一张图和上一张留存图做差分，
  即使设备检测漏报也不会完全错过鱼塘状态变化。
- 夜间可降低频率或只保留告警图。

## 二、可接入路径对比（前期调研结论）

| 路径 | 适用情况 | 结论 |
|---|---|---|
| 官方设备抓图 API `POST /api/lapp/device/capture` | 支持抓图的 IPC（`support_capture=1`） | ✅ 主用。单次返回 picUrl（约 2 小时有效），不下载视频 |
| 设备告警图片（alarmPicUrl） | App 内已开启移动/人形等侦测 | ✅ 最优先，只在事件时取图 |
| 局域网 RTSP（App 内"本地服务设置"开启） | 摄像头支持本地 RTSP | ✅ 若可用则最稳定，可完全本地做差分，不依赖云 |
| Home Assistant / Frigate | 有 NAS / 迷你主机 / 常开电脑 | 可选，适合做自动化和看板 |
| 开放平台"按间隔抓拍"任务 | 企业版套餐 + 云端存储 | ❌ 图片先落萤石云，不符合"不想存大量图" |
| 云录像 / NVR | — | ❌ 持续录像，与目标相反 |

## 三、API 链路（个人账号即可，免费）

1. **获取 accessToken**
   `POST https://open.ezviz.com/api/lapp/token/get`，参数 `appKey`、`appSecret`
   （开放平台控制台 → 应用管理创建应用获得）。Token 有效期约 7 天，需定期刷新。
2. **抓图**：`POST /api/lapp/device/capture`，参数 `accessToken`、`deviceSerial`、`channelNo`。
   每台设备间隔建议 ≥ 4 秒。仅适用于 IPC 或关联了 IPC 的 DVR。
3. **告警列表**：`POST /api/lapp/alarm/device/callAlarmList`，参数含时间范围、分页。
   返回每条告警的 `alarmPicUrl`（事件现场图）。
4. **消息推送（webhook）**：开放平台"消息推送"服务可让平台主动 POST 事件到指定地址，
   省得轮询；不开通则退化为每 1~2 分钟轮询一次告警列表。

## 四、图片保留策略

- 有变化：保留 30 天；
- 无变化：差分后立即丢弃；
- 磁盘占用超过阈值（如 5GB）：自动删除最旧的"有变化"图片。

## 五、待确认事项（决定最终走哪条链路）

登录萤石后只需确认三点（**不要把账号、密码、验证码、accessToken 发给任何人**）：

1. 摄像头**具体型号**、是否电池供电；
2. App 内是否有：局域网实况 → 本地服务设置 → **RTSP**；
3. 开放平台控制台能否创建应用、能否开通**消息推送**。

结论分支：
- 有 RTSP → 本地拉流抽帧 + 差分，云上只作辅助；
- 无 RTSP 但支持抓图/告警 → 走「告警图 + capture 兜底」的云上方案；
- 两者都不行 → 再考虑 HA 云端桥接（依赖非公开接口，最后备选）。

## 七、特殊情况：设备来自好友分享

当前摄像头的归属是**好友的萤石账号**，只分享给了用户。这带来一个关键限制：

- **好友分享（App 内分享）只给"看"的权限，不给 API 权限**。
  被分享者用自己的 accessToken 调用抓图/直播/告警接口，会被判为"该用户不拥有该设备"。
- 官方为此场景提供的正规机制是 **设备托管**：
  设备归属不变，但好友通过授权链接把指定权限（直播、抓图、消息等）授予用户的开发者账号，
  之后用户自己的 appKey/accessToken 即可调用这些接口。

### 重要更新：托管入口对个人账号可能不可见

经核实，设备托管分新老两代产品，门控不一致：老版 B2B 托管要求企业认证/付费客户、
邮件人工开通；新版"零开发托管"（控制台 → 萤石用户连接 → 设备托管服务，
直达 https://open.ys7.com/console/deviceTrusteeship.html ）虽宣传自助 5 分钟，
但个人开发者账号下是否显示该入口无保证（已实测反馈找不到）。
找不到时可邮件 open-team@ezvizlife.com 或客服 400-878-7878 申请开通。

设备主人明确不同意过户，故**主方案仍为设备托管**（归属不变、只授权接口权限，好友可随时收回）。

2. **勾选全部权限**（官方说明权限仅一次勾选机会，后续更改繁琐；若以后要接告警推送
   再补开发量），**生成授权链接**发给好友；
3. 好友打开链接，登录自己的萤石账号，**勾选鱼塘摄像头**，确认授权；
4. 用户回到托管控制台 → 设备列表，应能看到该设备；序列号填入 `监控网页.html` 即可按原计划使用。

### 设备过户（已被设备主人否决，留档参考）

1. 好友在自己的萤石云 App：设备设置 → 转移设备，将鱼塘摄像头过户到用户账号；
2. ~~用户成为设备主人~~（设备主人不同意，此路线废弃）。

### 托管备选方案（若设备过户不可行）

配置页面若要求填写**回调地址**：选择「不需要接收托管消息」即可——回调是平台主动推送
授权/设备变更通知的网址，本方案全部走主动轮询，不需要它。

注意事项：
- 好友若开了**视频加密**，API 取不到画面地址，需关闭该摄像头的视频加密后重新授权；
- 若抓图报权限错误，说明授权时勾选的权限范围不够，让好友重新打开链接补勾即可；
- 替代方案（都不如托管干净）：
  a) 好友把设备**过户**给用户 —— 权限最全，但好友失去设备；
  b) 好友自己注册开放平台、把 appKey/appSecret 给用户 —— 等于把账号 API 权限全交出，信任成本高；
  c) 若用户能到达摄像头所在局域网 —— 让好友在 App 里开"本地服务/RTSP"，本地取流做差分，完全不依赖账号归属（见第五节）。

## 八、自动录制（短片段）方案

需求映射（全部可用 `record.sh` 覆盖）：

| 需求 | 实现方式 |
|---|---|
| ① 定时录制（每 10 分钟录 20 秒） | launchd 每 600 秒跑一次 `record.sh timed`（见 plist 示例），或 cron |
| ② 触发录制（看到场景不对时录） | 手动：确认异常后跑一次 `record.sh triggered`；自动：后续由差分/告警服务调用 |
| ③ 重点时段录制（晚上偶尔录） | cron 限定小时范围 + `JITTER=1800` 随机抖动，例如每晚 19~23 点随机录 4 段 |
| ④ 关键动作录制（放鱼食等大变化） | 开通消息推送/webhook 后，人形/移动告警一到就触发 `record.sh triggered`；兜底用抓图差分检测突变 |

### 推荐链路：ffmpeg 直接拉云流（不经过 PC 客户端）

托管开通后，用 `POST /api/lapp/v2/live/address/get`（protocol=4 取 FLV 地址），
ffmpeg 直接录短片段：

```bash
ffmpeg -i "<flv直播地址>" -t 20 -c copy 片段.mp4
```

`record.sh` 已把「取 token → 取直播地址 → 录 N 秒 → 磁盘保护清理」串好，
填好 CONFIG 区的 APP_KEY / APP_SECRET / DEVICE_SERIAL 即可用。

注意事项：
- **H.265 编码的设备不能走 flv/hls/rtmp**（标准流仅支持 H.264），
  会报"视频编码非H264"。先在 `监控网页.html` 用高清档试播确认能出画面；
  若设备是 H.265，方案改用 ezopen 播放或让好友把编码改成 H.264。
- 直播地址有效期有限（默认 7 天，可按 expireTime 调整），所以 record.sh 每次运行时重新取地址，不要写死。
- Mac 睡眠时 launchd/cron 不执行：需在「系统设置 → 电池 → 选项」里防止自动睡眠，
  或把录制放到常开的 NAS/树莓派上跑（ffmpeg 跨平台，脚本基本不用改）。

### launchd 安装（Mac 常驻）

```bash
cp "com.yutang.record.plist.example" ~/Library/LaunchAgents/com.yutang.record.plist
launchctl load ~/Library/LaunchAgents/com.yutang.record.plist      # 装载
launchctl unload ~/Library/LaunchAgents/com.yutang.record.plist    # 停用
```

cron 版（晚上重点时段随机录 4 段示例）：
```cron
*/10 8-18 * * *  JITTER=0  "/Users/jiayang/代码/2026 鱼塘/录像与延时方案/record.sh" timed
3-59/15 19-23 * * *  JITTER=900  "/Users/jiayang/代码/2026 鱼塘/录像与延时方案/record.sh" timed
```

### 备选：PC 客户端内录（仅在托管走不通时考虑）

可以用 macOS 自带能力对「萤石工作室」窗口录屏：
`screencapture -V 20 -l <窗口ID> out.mov`，窗口 ID 用 AppleScript 定位；
或 ffmpeg 的 avfoundation 抓屏再 crop 裁剪出画面区域。

可行但脆弱：客户端更新/弹窗/掉线都会破坏固定窗口假设，且 Mac 必须保持登录、
亮屏、客户端停在预览页。只作为托管失败后的兜底路线，不建议作为主方案。

> 隐私说明：API 签发的直播地址为带 sign 的临时 URL，持链接即可播放但
> 无法被枚举发现，且默认 7 天过期。注意勿将链接贴到公开渠道，泄漏后
> 重新签发即可。

## 九、历史录像（SD 卡内录）批量下载

背景：录像每天落在摄像头 SD 卡上，萤石 PC 客户端仅有 Windows 版，
用 AI 助手逐个点击下载效率低。正确做法是**走 API 批量拉**（Mac 直接跑，无需 Windows）：

1. `POST /api/lapp/device/video/local/time` — 查某天是否有录像（hasVideo）；
2. `GET /api/v3/das/device/local/video/query` — 查当天录像片段列表
   （起止时间须在 24 小时内；可按 recordType 区分定时/事件/人形，需设备支持）；
3. `POST /api/lapp/v2/live/address/get`（type=2 本地录像回放，protocol=4 flv）— 取片段回放流地址；
4. `ffmpeg -i <地址> -t <时长> -c copy` 落盘为 mp4。

`download-recordings.sh` 已实现上述全流程：`./download-recordings.sh 2026-09-05` 下载整天，
缺省下载昨天。未拿到真实凭证前未实测；报错时脚本会把原始返回留在 `录像下载/` 目录便于定位。

备选路线（按推荐顺序）：
- **Mac 上装 Windows 虚拟机**（VMware Fusion 个人版免费 / UTM 免费）跑萤石工作室，
  局域网内可批量下载 SD 卡录像——不买新电脑，但仍是手工流程；
- **拔卡读卡器**：一次性导出最彻底，但文件格式与持续化都差，仅适合救急；
- **买台 Windows 迷你主机**：只有当你同时想要一台常开录制盒时才划算，
  单纯为下载录像而买不值——同样的钱买 NAS/树莓派跑本方案脚本更实用。

## 十、多路摄像头（4 路）

设备为 4 路 NVR/多通道机时，**所有接口按通道号（channelNo 1~4）分别调用**，
序列号填整机序列号即可：

- `监控网页.html`：通道填 `1,2,3,4` → 「播放全部通道」自动四宫格；「逐路抓图」按路循环
  （遵守官方 ≥4 秒间隔）；清晰度默认流畅（多路同屏流量×路数，宽带吃紧务必用子码流）；
- `record.sh`：CONFIG 里 `CHANNELS="1 2 3 4"`，每次运行逐路录 `timed_ch1_*.mp4` 这样命名，
  可改成只录关心的路（如鱼食投放点所在路）；
- `download-recordings.sh`：下载时循环各通道分别查片段即可（同接口，channelNo 不同）；
- 告警接口返回带通道号字段，可只对指定路的事件触发录制。
